# REMOTE SERVICE SECURITY AND PRIVACY COPY

## User-Facing Notice

SQX Edge Pro runs as a protected web service. You do not need to install Python, unzip tools or configure local dependencies. After signing in with your validated email, you use the application from your browser.

Your workspace is isolated from other users. Generated `.cfx` files, views, imports, exports and operational logs are stored in your private server workspace. Internal StrategyQuant X paths, templates and configuration are managed by the SQX Edge operator so you do not have to configure them on your computer.

The service is operated behind authenticated access, audit logging and controlled infrastructure. We use these controls to reduce installation friction, protect user workspaces and detect operational issues. No software platform can honestly promise "zero risk", so SQX Edge communicates a controlled, audited and isolated operating model instead.

## Short Version

Access SQX Edge Pro from a secure link. No local installation. No Python setup. No local SQX path configuration. Your work is processed in an isolated server workspace with authenticated access and operational audit.

## Support Copy

If you cannot access the service, contact support with your account email and the visible support reference from the app. Do not send passwords, private keys, full license files or raw payment payloads.

If a generated artifact looks wrong, send the non-sensitive artifact name, timestamp, asset, timeframe, BlockSetting and the support reference. The operator can use server-side audit logs to trace the request without exposing another user's workspace.

## Operator Boundaries

- Do not claim that the service has no risk.
- Do not expose internal server paths to users unless needed for support and redacted.
- Do not ask users to install local dependencies in the remote-service flow.
- Do not provide portable ZIP instructions as the primary commercial onboarding path.
- Keep payment, entitlement and workspace evidence out of public Git.
